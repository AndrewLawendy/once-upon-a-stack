Room in the Case

Keep my favourite

[[Della|the cache]] is fast because she's small and close. Small means she fills up.

On a busy day the case is full before any sticker runs out. A plum pie arrives, and there's nowhere to put it.

[[Rosie|your app]] has a favourite, and she wants it in the case when she comes in. For that, something has to go. But what?

What people see, if nothing goes: saving fails with OOM command not allowed when used memory > 'maxmemory'.

For grown-ups

The size of the case
Verified Redis's limit is maxmemory (default 0, no limit on 64-bit). "Whenever a client runs a new command that adds more data to the cache, Redis checks the memory usage. If it is greater than the limit, Redis evicts keys according to the chosen eviction policy until the total memory used is back below the limit."
The default is: don't throw anything out
Verified maxmemory-policy defaults to noeviction. At the limit, writes are rejected with the error above, and "commands that only read existing data still work as normal". Redis 7.4.0, src/config.c and src/server.c (shared.oomerr).
Why not keep everything
Inferred RAM is finite and costly. With no limit, the process grows until the operating system kills it.
